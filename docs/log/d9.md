## 三、卡在哪（写清楚，明天不再重复踩）

1. **np8 整组消失（两次）**：`nohup ... &` 起的压测脚本在 WSL 会话结束后被整组 SIGTERM，`ps` 里父脚本/服务/客户端全没了，`d9_run.out` 只停在该档头部，客户端是「一档跑完才写 CSV」，所以那 100 笔一行都没留下。**教训：长压测必须放同一个前台会话里跑，或至少每档结束就 flush 落盘。**
2. **`clocks.sm` 读到 315 MHz 是假象**：一开始以为高并发被降频，实际是档间/进程被杀后的空闲档位；补采 `results/d9_clocks.csv`（668 个样本）后确认负载期 p50 = **1800 MHz**、util p50 = 96%，没有降频。**以后判降频必须看负载窗内的样本，不能抓单帧。**
3. **`power.draw` 在 WSL 下恒为 `[N/A]`**：功耗这条证据拿不到，只能用时钟+util 代替，报告里已注明。
4. **口径修正**：方案里假设 prompt 200 token，实测中位 **140**；prefill 占 token 总量的 69%，不是 80%+，所以「prefill 抢占」的权重比原预期略低，但依然是 8→16 档躺平的主因。
