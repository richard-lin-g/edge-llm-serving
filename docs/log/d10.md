## 三、卡在哪（写清楚，明天不再踩）

1. **第一处失败的确切日志行**（不是 OOM，是 tokenizer 版本）：
   ```
   AttributeError: Qwen2Tokenizer has no attribute all_special_tokens_extended. Did you mean: 'num_special_tokens_to_add'?
   ```
   原因：uv 解析出 transformers 5.23.0，vLLM 0.8.5 用的是被移除的旧属性。修法：`pip install transformers==4.51.3`（连带 tokenizers 0.21.4、huggingface-hub 0.36.2）。修完一次起服务成功。

2. **判定码**：`vllm_classify.py` 对四份日志（L1 / L1b / L2 / CTRL）一致判 ARCH，触发条件是 sm75 的 `Compute Capability < 8.0 is not supported by the V1 Engine` 告警。服务运行本身零报错——它是走 V0 回退起来的，能起属服务层、ARCH 属架构层。
   但性能瓶颈归因 **KERNEL/BACKEND** —— 属"硬件/架构边界"（sm75 无 V1、无 FA2、AWQ 未优化），不是环境问题。
   三类 OOM（权重阶段 / KV 0 block / graph 捕获）今天**一个都没出现**。

3. **这轮踩到的环境坑**：
   - PEP 668：`pip install uv` 报 `externally-managed-environment` → venv 引导 uv（`~/.uvboot`）绕过，不动系统 Python 3.14。
   - 系统无 3.10–3.12，`python` 命令不存在 → `uv python install 3.12` 拉独立 CPython 3.12.16。
   - transformers 版本（见上）。
   - `Wsl/Service/WSAETIMEDOUT`：GPU 打满 + 并发开多个 `wsl.exe` 会话时触发，新会话进不来；`wsl --shutdown` 后恢复。压测改串行单会话。
   - 下载：tuna 源大文件只有约 1.4 MB/s，vLLM 全套约 4.3 GB，装了约 45 分钟。
