# D7 · 量化对照（2026-11-16，台式机 T600 4GB）

## 做了什么

- **补齐模型**：Q4_0（1.86 GiB）、Q8_0（3.37 GiB）从 hf-mirror 下完（Q4_K_M 1.96 GiB 是 11-12 就有的），三档共 **7.19 GiB**。
- **换尺子**：`/usr/bin/llama-bench` 是 Debian 打包的 CPU-only 构建（backend 列 = CPU，`-ngl 36` 无效；`ggml/backends0/` 无 CUDA 后端；WSL 无 nvcc、`~/llama.cpp` 已随 D4 重装消失）。改用仓库 CUDA 版 `bin/llama-server` + `bench/metrics.py` 的服务端自报口径（`srv_pp_tps` / `srv_tg_tps`），新写了 `scripts/d7_quant_speed.sh` 与 `bench/d7_speed_to_bench.py`。三档 **全部 `-ngl 36`**，可直比。
- **三档速度**（pp_n≈566、n=3 中位数）：Q4_0 **148.9 / 37.8**、Q4_K_M **147.3 / 33.5**、Q8_0 **141.4 / 25.5**（t/s，pp512 / tg128）。
- **三档采答案**：`bench/d7_eval.py collect`，10 题 × 3 档 = 30 条，**全部 10/10 成功**；显存峰值（含桌面基线 412 MiB）：Q4_0 2596 / Q4_K_M 2699 / Q8_0 **3863** MiB。
- **盲评**：30 条打乱成 A/B/C，**逐条对照每题 rubric 独立打分**（不横向比），fact/format/useful 三项 1–5 分 → `results/d7_scores.csv`，解盲后 `results/d7_quality.csv`。
- **质量结果**：Q4_K_M 与 Q8_0 并列 **3.43**，Q4_0 **3.17**；三档 **fact 全是 3.10**。

## 卡在哪、怎么解决

1. **没有 CUDA 版 llama-bench** → 不用 llama-bench，改用服务端自报口径；代价是绝对值和 D2 的 39.33 不同尺子（见下条）。
2. **Q4_K_M tg 比 D2 锚点 39.33 低 14.7%** → 先用 `-b 2048 -c 2048` 复测，tg 仍是 33.8，**排除批大小/上下文**；剩差异来自二进制：今天 `bin/llama-server --version` 是 `version: 0 (unknown)`（D4 重装后恢复的那份），D2 的 39.33 来自重装前的构建。**结论：D2 数字记历史，D7 只做同日三档互比。**
3. **Q8_0 在 4 GB 卡上能不能上 36 层** → 能，但显存峰值 **3863/4096，只剩 227 MiB**（桌面基线就占 412 MiB）。`load_tensors` 显示 `CUDA0 model buffer 3049 MiB + compute 301 MiB`，另有 393 MiB 留在 CPU mmap。所以"能跑"和"能交付"是两件事，报告里必须写峰值。
4. **`d7_quant_speed.sh` 里 `local m="$1" n="$2" log=...(用 $m)` 触发 `unbound variable`** → `local` 同一行里引用前一个变量不生效，拆成三行 `local`。
5. **`pkill -f "llama-server .*8084"` 把自己的 shell 一起杀了**（bash 的 cmdline 里含同样字符串，退出码 15）→ 按端口精确匹配，或干脆在脚本里用 `$!` 记 PID。
6. **Q4_K_M / Q8_0 明明 D2 测过还要重测** → 因为拼表会让结论翻转（D2 的 39.33 拼今天的 Q4_0 37.8 会得出"Q4_0 更慢"）。逐项对账与理由写在 `docs/quant-comparison.md` §6.5「与 D2 数据的复用审计」。顺带钉死了 §6 的归因：同一天里只有 K-quant 掉了 15%，Q8_0 只掉 5.2%。

## 今天最硬的一条结论

**量化不是"越小越快"**：Q4_0 体积只比 Q4_K_M 小 5%，tg 却快 **12.7%**（37.8 vs 33.5），赢在 Q4_0 的 32-元素 block 反量化只有一次 fp16 scale 乘法，而 Q4_K_M 的 256-super-block 要解两级 scale、多一轮整数运算 —— 在 T600 这种低算力小卡上，反量化的 ALU 开销压过了那 5% 的体积差。

配套两条：
- **Q8_0 质量没赢**：和 Q4_K_M 同为 3.43，且三档 fact 全 3.10 —— q05 三相功率三档全算错、q08 KV Cache 三档全说成"数据库缓存"，**换量化救不了模型容量**。
- **Q8_0 三项全输**：显存只剩 227 MiB、tg 慢 24%、体积 +72%，边缘不做默认。
