| 中途失败 | `llama-server` 缺 `tools/server/public/bundle.css`、`bundle.js`（Debian dfsg 版删掉了 web UI 资源）→ 加 `-DLLAMA_BUILD_WEBUI=OFF` 后编译通过 |
| `llama-cli` | 编译成功 |

| CUDA 链接验证 | `ldd` 命中 `libggml-cuda.so.0`、`libcudart.so.13`、`libcublas.so.13`、`libcublasLt.so.13`、`libcuda.so.1`（`/usr/lib/wsl/lib`）—— **没有静默退化成 CPU** |
| 运行时 | **失败**：`ggml_cuda_init: failed to initialize CUDA: CUDA driver version is insufficient for CUDA runtime version` |

原因：Windows 侧驱动 **572.83**，`nvidia-smi` 显示 `CUDA Version: 12.8` 是驱动上限；而 runtime 是 **13.3**，高过上限即拒绝初始化。

### 三个 CUDA 版本各自的失败原因（别混为一谈）

| CUDA | 编译 | 失败原因 | 错误特征 |
|---|---|---|---|
| 12.6 | ✗ | **host 编译器版本太高** | `unsupported GNU version! gcc versions later than 13`；加 `-allow-unsupported-compiler` 后 54 errors |
| 12.8 | ✗ | **glibc 头文件冲突**，与 gcc 无关 | `bits/mathcalls.h: exception specification is incompatible ... "cospi"`，换 `-ccbin g++-14`、换 `-std=c++11/14/17` 均为 6 errors |
| **13.3** | ✓ | 无 | 运行需驱动 **≥ 580** |

结论：26.04 上只剩一条路 —— **把 Windows 侧驱动升到 580+**（580 系列 release notes 明确支持 Turing + CUDA 13.x）。
升级前，GPU 版二进制已放在 `~/edge-llm-serving/bin/`（连同 `libggml*.so*`），驱动就绪后可直接用。

## 四、修复的脚本 bug

`d4_sse_check.sh` 原来用 `date +%s%3N` 计时，在 WSL2 上出现 `+621289682ms` 甚至负数——WSL2 的系统时钟跟随宿主机休眠/唤醒跳变。

改为用 `/proc/uptime` 单调钟取毫秒（`now_ms()`）。分片计数、正文拼接、PASS/FAIL 判定逻辑不变。

用 `/completion`（非流式）打 **520 token 输入 / 128 token 输出**，直接读响应里的 `timings`：
